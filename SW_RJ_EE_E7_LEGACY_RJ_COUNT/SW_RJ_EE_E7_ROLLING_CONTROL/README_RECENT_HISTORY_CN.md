# 旧版参考：E4自适应分环＋近期FIFO候选历史

> 本文件只保留E4/E5历史设计。当前E7请先阅读 `README_先读我.md`。

当前包为E4.2：显式预声明`edge_updates`诊断结构字段，并把自测中的等逆温度
`[1 1]`改为合法的冷/热逆温度`[1 0.5]`。两处都只修复测试/诊断，不改变反演算法。

本版本以 `SW_RJ_EE_ADAPTIVE_complete` 为基线，只改变自适应EE的候选历史管理。
Birth、Death、Move、Change、似然能量、温度、先验、正演和原绘图不变。

## 默认日程

| 迭代 | 分环 | EE候选历史 |
|---|---|---|
| 1:3000 | 1001:3000用于第一次校准 | 不保存候选 |
| 3001:4000 | 边界固定 | 开始填充近期档案 |
| 4001:18000 | EE开启；每2000轮更新边界 | 每链严格保留最近4000个完整状态 |
| 18000轮结束 | 最后更新并冻结边界 | 删除预热过渡档案 |
| 18001:20000 | 边界固定；EE仍可用 | 从空档案重新填充，作为过渡期 |
| 20001:40000 | 后验收集 | 继续使用每链最近4000个状态 |

## 与E3全历史版的区别

E3每次改变边界后，把校准结束以来的所有模型重新归环，档案持续增长。
E4使用固定容量的循环FIFO。新状态写入时，若档案已满，就精确覆盖该链最早的状态；
旧状态同时从所属能量环索引中删除。每条链始终最多保存 `ee_archive_window` 个状态。

边界更新仍使用最近 `ee_adapt_window` 轮能量。边界改变后，只对当前仍有效的FIFO
状态重新归环，不重新正演、不去重、不按失配筛选。重复状态仍表示真实停留时间。

最终冻结边界时，默认执行一次档案清理。这样正式后验阶段不会继续抽到早期高失配、
过渡性的模型。清理后可能短暂出现EE不可用自循环，这是设计行为，不会补做第二次RJ。

## 新参数

```matlab
cfg.ee_archive_window = 4000;          % 每条链保留的最近完整状态数
cfg.ee_reset_archive_at_freeze = true; % 第18000轮冻结边界后清空预热档案
cfg.run_label = 'E4_recent_history';
```

`ee_archive_window` 是候选模型档案长度；`ee_adapt_window` 是计算边界的能量窗口。
两者默认都为4000，但含义不同，可以分别设置。

## 运行

```matlab
clear functions
run_self_tests
check_true_model_forward
file = Run_recent_history_EE;
inspect_adaptive_ee(file)
```

输出的 `EE.archive_seen`、`EE.archive_dropped`、`EE.archive_reset_discarded` 和
`EE.archive_reset_at` 用于检查FIFO及冻结清理是否按预期运行。

## 实验解释限制

这是借鉴 `EE.zip` “遗忘过时历史”思想的工程实验版，不是Kou等原始EE算法的逐行实现。
固定长度FIFO使候选经验分布持续变化，因此不能仅凭标准EE接受式宣称有限样本严格收敛。
必须与E3全历史版、早启动固定环版及EE关闭版使用相同种子和预算比较，并用独立种子重复。
